# Matcha Music — c12n version (clean-room rebuild of MatchaMusic 1.7.0 IPA)

Original IPA analysed 2026-10-29: bundle com.raiden.matchamusic, v1.7.0 (10700), min iOS 17.0, iPhone+iPad, portrait iPhone / all iPad, background audio+fetch, file sharing + open-in-place, NSAppleMusicUsageDescription, NSLocalNetworkUsageDescription, ATS arbitrary loads + local networking, UILaunchScreen {} (already correct), SwiftUI + AVFoundation/AVQueuePlayer + MediaPlayer + SQLite3, no third-party deps.
Our version: bundle com.c12n.matchamusic, name "Matcha Music", Copyright (c) 2026 c12n Apps, MIT, NO mention of the end user's personal name anywhere GitHub-visible.

## Original feature set (from binary strings / file list)
Files: AppModel, Backend, Models, Servers, Settings, Theme, Artwork, Lyrics, PlayHistory, StreamCache, Downloads, Equalizer, Player, Mixes, SpotifyImport, LocalBackend, SubsonicAPI, JellyfinAPI, PlexAPI; UI: Navigation, Shell, Components, LibraryScreens, DetailScreens, SearchScreen, StatsScreens, SettingsScreens, NowPlaying.
- Backends (protocol MusicBackend): (1) On-device Music library via MediaPlayer (MPMediaQuery songs/albums/artists/playlists, artwork, playback via AVPlayer on asset URL / MPMusicPlayerController fallback is NOT used - use AVPlayer where possible, graceful message if DRM/no URL). (2) Subsonic/Navidrome: /rest/ping, getArtists, getAlbumList2, getAlbum, getSong, getPlaylists, getPlaylist, search3, stream.view?id=, getCoverArt.view?id=, star/unstar, createPlaylist/updatePlaylist, scrobble; auth = token+salt MD5 (v1.14) with password fallback param, salt persisted per server. Server URL example in binary http://192.168.1.10:4533. (3) Jellyfin: POST /Users/AuthenticateByName {Username,Pw} -> AccessToken+UserId, header X-Emby-Token / MediaBrowser client="Matcha Music", GET /Users/{id}/Items (Audio, recursive, AlbumArtists/Albums/Songs), /Items/{id}/Image/Primary, stream /Audio/{id}/stream?static=true&api_key=, playlists /Playlists, favourite /Users/{id}/FavoriteItems/{id}. (4) Plex: PIN flow https://plex.tv/api/v2/pins?strong=true + https://app.plex.tv/auth, X-Plex-Client-Identifier persisted UUID, GET https://plex.tv/api/v2/resources?includeHttps=1&includeRelay=1, server /library/sections, /library/metadata/{id}/children, /photo/:/transcode, universal transcode /music/:/transcode/universal/start.mp3, token header X-Plex-Token.
- Multi-server: many ServerConfig entries, one default server. Albums/Artists/Songs/Playlists tabs show the DEFAULT server; Home, Search and Favourites aggregate ALL servers + local. Removing a server removes its library; downloads stay.
- Library UI: Home (shelves: AlbumShelf, SongShelf, recently played, mixes), Albums, Artists, Songs, Playlists, Search (across all servers), Favourites (tap heart on any song), Downloads (offline songs, "Available Offline", remove all), Stats (SQLite plays table: song_id,title,artist,album,album_id,artist_id,cover_art,duration,played_at,ms_played; Top songs/artists/albums, first/last played, day-minutes chart via Charts framework, "A year ago this month", never-played / least-played / forgotten favourites mixes), Mixes (songs you loved but haven't heard in 90+ days etc.), Artist detail (bio from Wikipedia REST summary, similar + photo from Deezer api.deezer.com/artist + /search/artist), Album detail, Playlist detail (download & keep in sync - new songs auto-download), Spotify import (paste public open.spotify.com/playlist link, read https://open.spotify.com/embed/playlist/ page track list, match against server search, create playlist; clear errors for empty/changed page).
- Player: AVQueuePlayer, queue pane, save queue as playlist, shuffle/repeat, gapless pre-buffer next songs ("Buffers the next songs so they start instantly"), stream cache on disk, Now Playing info + remote commands (MediaPlayer), AirPlay (allowsExternalPlayback), sleep timer incl. "End of current song" / "Sleep at end of song", equalizer (AVAudioUnitEQ, presets + custom bands, applies to streamed+downloaded), play history recording + optional "Record Plays on Server" scrobble, visible error "Couldn't play this song" with retry, lyrics (LRCLIB https://lrclib.net/api/get + /api/search, synced LRC parsing + plain fallback, toggle in Settings, pane in Now Playing).
- Artwork resolver fallback chain when server has none: server artwork -> Deezer (api.deezer.com/search/album, /search/artist) -> iTunes Search (itunes.apple.com/search) -> Cover Art Archive via MusicBrainz (musicbrainz.org/ws/2/release-group/ -> coverartarchive.org/release-group/{id}/front). Only artist/album/title sent. Disk cache artwork.
- Downloads: download songs/albums/playlists (original quality always), progress (ProgressDownload), offline playback from local files, storage usage + Remove All Downloads.
- Settings: streaming quality / transcoding choice (original vs transcode, container/protocol), cellular?, artwork & lyrics toggles + data-source credits screen (LRCLIB CC0, Wikipedia/Deezer CC BY-SA etc.), servers management, appearance/skins (original had SkinId skins: default matcha green + warm cream soft rounded; near-black Spotify-green circular art; brushed-silver iPod glossy + ClickWheel - DO NOT copy those skins verbatim; replace with our house style below), About "Matcha Music v…", feedback.

## House fixes + style to apply (from Viu Live TV v1.3.1 + AlRashid Prayer v1.1.2) — MANDATORY
1. TestFlight-safe project: DEVELOPMENT_TEAM=QD29U585ZA, CODE_SIGN_STYLE Automatic, ITSAppUsesNonExemptEncryption=false, UILaunchScreen as a DICTIONARY (never empty UILaunchStoryboardName - Apple error 90475), iOS 17.0 min, hand-written project.pbxproj must parse.
2. Appearance: Settings -> Appearance segmented Picker System/Light/Dark (persisted key matcha_appearance_mode), applied via .preferredColorScheme at root. Accent picker: matcha green (default), blue, purple, pink, orange, teal, red - with matching tint across tab bar, buttons, progress.
3. Text Size: AlRashid-style Settings picker Standard/Large/Extra Large mapping to .large/.xxLarge/.accessibility1 via .dynamicTypeSize at root, PLUS all rows use Dynamic Type font styles (.title3 semibold name, .body secondary, .callout tertiary) never fixed-pt text for content. 54pt+ artwork in rows, bigger hearts/buttons (min 44pt targets).
4. Liquid Glass: iOS 26 glassEffect cards/controls/mini-player/tab chrome with Material fallback on iOS 17-25 (copy the GlassHelpers pattern: GlassCardBackground, GlassControlBackground, GlassGroup/GlassEffectContainer). Availability-guarded so it compiles with Xcode 26 / macos-26 runner.
5. Whole-row taps: rows are ONE plain Button for the main action; secondary actions (heart, menu) are overlaid/separate buttons - NEVER a Button inside a Button/NavigationLink. No swipe-across-the-list gestures that hijack scrolling (Viu v1.3.1 lesson) - tab/filter switching by taps only; standard .swipeActions are OK.
6. Loading: parallel fetches (async let / TaskGroup), disk cache for library lists + artwork so relaunch is instant with background refresh, lenient Codable decoding (one bad/missing optional field must not fail a whole list - decode server fields leniently).
7. Errors are visible and recoverable: never a blank/black screen; player error shows message + Try Again; server-unreachable shows "Can't reach your server" + remove/re-add hint + retry; session-expired shows sign-in again prompt instead of silently empty library.
8. Secrets in Keychain only (server passwords, Jellyfin/Plex tokens) - never UserDefaults/plain files. Only non-secret config (name, URL, username, type, default flag) in UserDefaults/JSON.
9. Haptics light on taps, firmer on favourite (toggleable in Settings -> Appearance, Viu-style).
10. Layout by device idiom (iPad split view sidebar+detail) NOT by size class, so rotation never rebuilds the player/queue.
11. Settings rows: whole-row tappable with checkmark on the active choice (AlRashid v1.1.1 pattern), instant repaint on theme/accent change, no restart needed.
12. Privacy: no tracking/analytics/ads; About/Settings privacy footer stating data stays between the phone and the user's own servers; third-party lookups (lyrics/artwork) disclosed with exactly what is sent.
13. Dual ship: GitHub Actions workflows like Viu's - build-ipa.yml (unsigned IPA artifact + release), simulator-test.yml (boot iPhone iOS 26, install, launch, screenshot), testflight.yml (archive with automatic signing via ASC API key -allowProvisioningUpdates, altool upload). Version 1.0.0 build 1 for our rebuild (do not reuse 1.7.0).

## Stack constraints

Xcode 26 on macos-26 runner.

## Added features (user request 2026-10-29 "add other features that will work") — only reliable, no-extra-entitlement features
A. Local Files: import audio files/folders from the Files app (fileImporter, security-scoped bookmarks), copy into Application Support/LocalFiles, extract metadata/artwork with AVAsset (common metadata), playable/searchable/favourite-able like local-library songs, deletable. Uses existing UIFileSharingEnabled + LSSupportsOpeningDocumentsInPlace.
B. Widgets (WidgetKit, App Group group.com.c12n.matchamusic): small + medium Home Screen widget (Now Playing snapshot + top favourites/recently played from a shared snapshot JSON the player/app writes to the app group), Lock Screen accessory rectangular (current / last played song + artist). Timeline refreshes on track change via WidgetCenter reload from the app. Entitlements file for app + widget with the app group, DEVELOPMENT_TEAM QD29U585ZA pattern like AlRashid.
C. Siri + Shortcuts (AppIntents, iOS 17): AppShortcutsProvider with PlayFavouritesIntent, ShuffleAllIntent, PlayRecentlyPlayedIntent — each opens the app and posts a command the AppModel consumes on appear/foreground (honest implementation, no background playback claims).
D. Genre + Decade browsing and shelves: genres() per backend, Recently Added shelf, Random/Shuffle-All shelf, decade filter from year on albums/songs where the server supplies a year.
E. Song Radio / Instant Mix: similarSongs(song) per backend — Subsonic getSimilarSongs2, Jellyfin GET /Songs/{id}/InstantMix?UserId=, Plex same-artist + same-genre tracks from the section; UI "Start Radio" in song/album/artist menus, builds a queue.
F. ListenBrainz scrobbling (optional, off by default): user pastes their ListenBrainz user token in Settings (Keychain), player posts playing_now + listen to https://api.listenbrainz.org/1/submit-listens with Authorization: Token; failures are silent/logged, never block playback. (No Last.fm — it needs a shared API secret, so it would NOT reliably work.)
G. Sort + badges: Albums/Songs sort menu (A–Z, Newest, Year, Most Played where stats exist); rows show a format badge when known (codec/suffix + bitrate from Subsonic fields, Jellyfin media sources lenient, Plex part fields) e.g. "FLAC 941k".
H. Queue/context actions everywhere: Play Next, Add to Queue on songs/albums/playlists/artists; multi-select in Songs list for Add to Playlist / Download / Favourite batch actions.
I. Settings backup: Export/Import servers + preferences as JSON via share sheet / fileImporter — passwords and tokens are EXCLUDED from the export and the UI says so plainly.
J. Auto-download favourites toggle (new favourites download automatically when on Wi-Fi) and an Offline Mode toggle (hides non-downloaded/non-local content, player only queues local files).
Explicitly NOT added (would not reliably work): CarPlay (needs an Apple entitlement approval), Last.fm (needs a shared secret), Chromecast audio (unverified for this player chain — do not ship untested).
